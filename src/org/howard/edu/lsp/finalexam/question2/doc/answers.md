The abstract Report class defines the template method generateReport() and marks it final so subclasses cannot change the workflow. generateReport() fixes the order of steps: loadData() → print === HEADER === and formatHeader() → print === BODY === and formatBody() → print === FOOTER === and formatFooter(). The four step methods are declared protected abstract, so StudentReport and CourseReport are required to vary only those individual steps while inheriting an identical workflow/output. The driver stores both subclasses in a List<Report> and calls generateReport() on each. The same call  runs different concrete steps depending on the runtime type, which is polymorphism with the Template Method pattern.
