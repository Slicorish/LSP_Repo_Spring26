After completing Assignment 3, which involved refactoring my ETLPipeline code from Assignment 2, I recognized that the most significant improvements centered around encapsulation, object creation, and adhering to the single responsibility principle. In the original implementation, most of the functionality was contained within a single class. However, in the refactored version, the ETLPipeline was divided into four distinct classes, each with a clearly defined purpose. This restructuring made the code more organized, readable, and easier to maintain.

The introduction of the CSVReader and CSVWriter classes greatly improved how file input and output were handled. By separating these responsibilities, the code became cleaner and more reusable for future projects that require reading from or writing to CSV files. Additionally, the Product class played a key role in simplifying data processing. It allowed for easier manipulation of product data, such as determining whether a product is premium, applying discounts, and categorizing price ranges.

In my opinion, the ProductParser class was the most important component of the refactor. This class is responsible for parsing raw CSV data into a structured and usable format. It trims unnecessary characters and converts values into appropriate data types such as strings, integers, and doubles. This step made the rest of the data processing more efficient and reliable. I also found that using private and public attributes helped reinforce encapsulation by controlling access to data within each class.

Initially, when I asked ChatGPT to help refactor my code, it suggested implementing a Transformer interface and using inheritance. However, given the scope of the assignment, I felt that approach was unnecessarily complex. Instead, I chose to implement the transform logic as a helper method within the Product class. By doing so, I was able to call methods like applyDiscount and categorize directly within that helper method, resulting in a simpler and more straightforward design.

Another concept I learned during this process was the use of the Optional class. Optional represents a value that may or may not be present, helping to avoid null values and potential runtime errors. This provided a safer way to handle missing or invalid data, which was a new and valuable concept for me.
